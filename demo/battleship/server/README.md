# Морской бой: сервер

Авторитетный сервер игры. Хранит обе доски в памяти, принимает выстрелы и
возвращает результат, а не состояние. Поле противника клиенту не отдаётся
никогда — ни в каком виде, даже после конца партии.

Запуск:

```
python demo/battleship/server/main.py --port 8000
```

Клиент открывается на http://127.0.0.1:8000/ — сервер раздаёт статику из
`demo/battleship/web/`. Можно открыть и файлом (`web/index.html`): на
`/api/*` разрешён CORS для любого origin.

Перезапуск сервера обнуляет партию: состояние целиком в памяти.

## Протокол (HTTP + JSON)

Корни: `POST /api/game` — создать матч или присоединиться к ожидающему.
Один матч за раз: свободный слот есть только у партии в фазе `waiting`.

Все координаты — `x`, `y` от 0 до 9 (x — столбец, y — строка).

### POST /api/game
Тело пустое (`{}`). Ответ:

```json
{"game_id": "...", "player_id": "...", "phase": "waiting", "your_turn": null}
```

Второй подключившийся попадает в тот же матч; кто ходит первым — решает
сервер броском монетки (`your_turn: true/false` в момент старта).

### GET /api/game/{game_id}/state?player_id={player_id}
Полное состояние для одного игрока:

```json
{
  "phase": "waiting | playing | finished",
  "opponent_connected": true,
  "your_turn": true,
  "board": [["ship", "miss", "..."]],
  "enemy_view": [["unknown", "miss", "..."]],
  "enemy_sunk": [3],
  "my_sunk": [],
  "game_over": false,
  "winner": null
}
```

- `board` — только СВОЁ поле: `empty | ship | hit | sunk | miss`.
- `enemy_view` — то, что видно у противника: `unknown | miss | hit | sunk`.
  Корабли противника не раскрываются; `sunk` появляется только на клетках
  потопленного корабля (они и так были известны как попадания).
- `winner` — `player_id` победителя или `null`. Игра не заканчивается ничьей:
  ходы строго по очереди.

### POST /api/game/{game_id}/place
`{"player_id": "...", "ships": [[{"x":0,"y":0},{"x":1,"y":0}], ...]}`

Расстановка своего поля. `ships` можно не передавать — сервер расставит
случайно. Флот: 1×4, 2×3, 3×2, 4×1, корабли не касаются друг друга даже
углами. Перестраиваться можно, пока не сделан первый выстрел в матче.

### POST /api/game/{game_id}/fire
`{"player_id": "...", "x": 3, "y": 7}`

Ответ:

```json
{"result": "miss | hit | sunk", "sunk_ship": {"size": 3, "cells": [...]},
 "game_over": false, "winner": null, "your_turn": true}
```

`sunk_ship` присутствует только при `result: "sunk"` и называет размер и
клетки потопленного корабля — этого достаточно, чтобы честно помечать
ореол потопленного и считать оставшиеся корабли.

Правило чередования: попадание — стреляешь снова, промах — ход переходит.

Ошибки: JSON `{"error": "текст"}` со статусом 400 (некорректный выстрел),
403 (чужой player_id), 404 (нет матча), 409 (не твой ход, матч полон,
расстановка заперта).

Клиент узнаёт о ходе противника опросом `state` (раз в секунду достаточно).
